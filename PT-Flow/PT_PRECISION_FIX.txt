PT-FLOW BF16 GENERATOR -> FP32 POTENTIAL FIX

Diagnosis from smoke job 16115753
-------------------------------
Training failed when the proximal loss switched on:
  RuntimeError: mat1 and mat2 must have the same dtype,
  but got BFloat16 and Float

The generator returned BF16 samples. The potential used FP32 linear weights
without converting those samples. This was a code-level precision boundary
error. The dispatcher cancellation was the intended afterok failure behavior.
The displayed 31.35 seconds is a first-iteration measurement, not a reliable
steady-state throughput measurement. This patch does not establish GPU speed
or FID quality; the full A100 smoke test still needs to pass.

Fix
---
Only two runtime files change: ptflow/potential.py and utils/precision.py.
PotentialNet and ScaleNet convert inputs to their parameter dtype without
detaching the autograd graph. FP32 heads explicitly disable ambient autocast.
Potential input gradients and the combined CFG branches operate in FP32.
Generator BF16, architecture, checkpoint parameter names, objective, dataset,
4k budget, Slurm resources, W&B and output locations are preserved.

load the fixed modules. All future ablation arms use the same corrected code.

Regression scope
----------------
The exact BF16/FP32 exception was reproduced locally before the fix. Tests
cover FP16/BF16 inputs, FP32 potential and scale outputs, input/parameter
gradients, both proximal-loss modes, higher-order CFG gradients, training
smoke tests and checkpoint compatibility. The included check additionally
executes four-step Mode B with BF16 generator outputs, without a GPU.
